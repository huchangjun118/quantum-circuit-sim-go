# 量子线路仿真与态矢量查看工具

本工具使用 Go 实现本地量子线路仿真。输入手写线路描述后，工具会按声明顺序完成态矢量演化，输出可复现的态矢量、测量结果、ASCII 线路图以及每个指令阶段的态矢量。

## 构建与运行

```bash
go build -o qcsim .
./qcsim examples/bell.qc --shots 20 --seed 42 --stages bell-stages.json
```

也可以从标准输入读取线路：

```bash
cat examples/ghz3.qc | ./qcsim
```

常用参数：

- `--file`：线路文件；也可以把文件路径作为第一个位置参数。
- `--shots`：测量采样次数。
- `--seed`：随机种子；相同种子产生完全相同的采样序列。
- `--diagram`：是否输出线路图，默认 `true`。
- `--state`：是否输出最终态矢量，默认 `true`。
- `--stages`：把每条指令执行后的态矢量写入 JSON 文件。
- `--json`：输出机器可读 JSON。

## 线路描述语法

线路文件是按行书写的文本，`#` 之后为注释。

### 寄存器声明

```text
qubits 3
cbits 2
```

- `qubits N`：声明量子比特数，必须存在且只能声明一次。
- `cbits N`：声明经典比特数。若省略且线路中有测量语句，会根据测量目标自动推断。
- 声明必须出现在任何门或测量操作之前。

### 门操作

门操作的一般格式为：

```text
<操作比特列表>: <门名>(<参数>)
```

比特列表使用 `q0`、`q1` 这样的名称，支持空格或逗号分隔。例如：

```text
q0: H
q0: RX(1.5707963267948966)
q0 q1: CX
q0 q1 q2: CCX
```

受控门和多比特门的比特顺序如下：

- 两比特受控门：前面是控制比特，最后一个是目标比特。
  - `CX` / `CNOT`、`CY`、`CZ`、`CH`
  - `CP(theta)`、`CRX(theta)`、`CRY(theta)`、`CRZ(theta)`
- `SWAP`：两个目标比特交换。
- `CCX` / `CCNOT`：前两个是控制比特，最后一个是目标比特。
- `CSWAP`：第一个是控制比特，后两个是交换目标。
- `MCX`：除最后一个比特是目标外，其余全部是控制比特。

支持的单比特门包括：

- `I` / `ID`
- `H`
- `X`、`Y`、`Z`
- `S`、`SDG`
- `T`、`TDG`
- `SX`
- `RX(theta)`、`RY(theta)`、`RZ(theta)`
- `P(phi)`
- `U(theta, phi, lambda)`

门名不区分大小写。参数使用十进制浮点数，例如 `RX(1.234)`；`U` 需要三个参数，例如 `U(1.0, 2.0, 3.0)`。

### 测量

测量语句格式为：

```text
<量子比特列表> -> <经典比特列表>
```

例如：

```text
q0 -> c0
q1 q2 -> c1 c2
```

测量采用计算基投影测量。测量会导致态矢量坍缩，经典比特保存对应结果。

### Bell 态示例

`examples/bell.qc`：

```text
qubits 2
cbits 2
q0: H
q0 q1: CX
q0 -> c0
q1 -> c1
```

## 错误定位与拒绝策略

解析器会先完整解析并校验整条线路，然后才开始仿真；因此非法线路不会产生半成品状态。

语法错误返回 `parse error at line L, column C: ...`，可定位到具体行列。

语义错误返回带类别的错误，可通过 `errors.Is` 判断：

- `qubit_out_of_range`：量子比特越界。
- `classical_bit_out_of_range`：经典比特越界。
- `missing_parameter`：缺少门参数或参数数量错误。
- `invalid_parameter`：参数无法解析。
- `unknown_gate`：门名称无法识别。
- `invalid_gate_arity`：门的操作比特数量错误。
- `conflicting_declaration`：重复声明、重复使用经典比特、同一门中重复比特、测量两侧数量不一致等。
- `missing_qubits_header`：缺少 `qubits` 声明。

## 确定性与测量复现

- 态矢量使用 `complex128` 稠密向量和确定性浮点运算。
- 同一份输入多次仿真得到的态矢量逐位一致。
- 测量采样使用 PCG 随机源，种子由 `--seed` 指定。
- 相同种子、相同线路和相同采样次数会得到完全相同的结果序列。
- 每次测量后，态矢量只保留与采样结果对应的坍缩分支，并按概率重新归一化。阶段导出文件中的 `outcomes` 与对应阶段的 `state` 严格对应。

## 输出内容

### 线路图

ASCII 线路图按指令声明顺序绘制，例如 Bell 态：

```text
q0: ───H──────●──────M──────────
q1: ──────────⊕─────────────M───
```

### 态矢量

默认输出最终态矢量，包含基矢、振幅和概率。基矢字符串按 `q0 q1 ...` 的顺序排列，例如 `|10>` 表示 q0 为 1、q1 为 0。

### 采样

指定 `--shots` 后，每次采样都从初始态重新执行整条线路，并共享同一个随机流。输出包含每次采样的比特串和计数。

### 阶段态矢量

`--stages` 导出 JSON，包含：

- 每条指令的序号；
- 门名称、控制比特、目标比特和经典目标；
- 测量结果；
- 该指令执行后的完整态矢量。

## 性能与规模

仿真器使用稠密态矢量，内存复杂度为 `O(2^n)`，这是态矢量方法的固有复杂度。门作用采用按比特掩码的原地更新，避免每条门额外分配状态数组；受控门和交换门也按相同掩码方式高效更新。

测试中包含 20 量子比特 GHZ 态的构建与采样验证。当前代码设置的安全上限为 30 量子比特。

## 自动化测试

运行全部测试：

```bash
go test ./...
```

测试覆盖：

- 合法线路解析；
- 未知指令、未知门等语法错误；
- 量子比特和经典比特越界；
- 缺失参数、非法参数和错误元数；
- 重复声明、重复操作比特、重复经典写入等冲突；
- Bell 态、GHZ 态、Pauli 门和 SWAP 门的态矢量正确性；
- 重复仿真的态矢量逐位确定性；
- 测量坍缩与结果的对应关系；
- 多次采样的可复现性；
- 阶段导出的顺序和目标；
- 20 量子比特规模输入。

## 项目结构

- `internal/circuit`：线路解析、语义校验和错误类型。
- `internal/simulator`：态矢量演化、门矩阵、测量和采样。
- `internal/diagram`：ASCII 线路图生成。
- `internal/cli`：命令行接口、结果展示和 JSON 导出。
- `examples`：示例线路。
